# บทพูด Demo — แบบสั้นและเป็นธรรมชาติ

## เปิดเรื่อง (20–30 วินาที)

“งานนี้ผมจำลองข้อมูลการขายของร้านเสื้อผ้าบน TikTok Shop แล้วทำ Pipeline นำข้อมูลจากไฟล์ต้นทาง เข้า Database ผ่าน Data Lake และมาสรุปยอดที่ Warehouse ครับ วันนี้จะโชว์สองรอบ คือข้อมูลตั้งต้นกับข้อมูลที่เข้ามาทีหลัง แล้วทดสอบว่ารันซ้ำและแก้ปัญหาได้ไหม”

| หน้าจอ | พูดแค่ไหน | ชี้ผลตรงไหน |
|---|---|---|
| **00 เตรียมโปรเจกต์** | “ตรงนี้โหลด Code และไฟล์ข้อมูลจาก GitHub มาที่ Colab ครับ” | ชื่อโปรเจกต์และจำนวนไฟล์ Source |
| **01 Run 1** | “รอบแรกเอาข้อมูลเดือนตุลาคมเข้าครบทุกชั้น ตั้งแต่ SQLite จนถึง Warehouse ครับ” | จำนวนรายการ ยอดขาย และผลตรวจผ่าน |
| **02 Run 2** | “รอบสองมี Order ใหม่และข้อมูลเดิมที่เปลี่ยน เช่น เพิ่งชำระเงินหรือมีต้นทุนเข้าช้า เราอัปเดตเฉพาะส่วนที่เปลี่ยนครับ” | ตัวเลขก่อน/หลัง แล้วกดรันซ้ำให้เห็นยอดเท่าเดิม |
| **03 ตรวจยอด / Lineage** | “ตรงนี้ตรวจว่ายอดใน Database กับ Warehouse ตรงกัน และตามได้ว่าตัวเลขมาจาก Order ไหนครับ” | PASS/FAIL และ Order ID ตัวอย่าง |
| **04 Error Recovery** | “ผมจำลองให้ Transform ผิดก่อน ระบบจะบอกสาเหตุ แล้วแก้และรันต่อจากขั้นนั้น ไม่ต้องเริ่มใหม่ทั้งหมดครับ” | Error Code, Retry Stage, PASS |
| **05 Performance / KPI** | “ส่วนสุดท้ายวัดเวลาทำงานจริง และดูยอดขาย ต้นทุน กับกำไรที่ได้จาก Warehouse ครับ” | เวลาประมวลผล, รายการ/วินาที และกำไร |

## ปิดเรื่อง (10–15 วินาที)

“สรุปคือ Pipeline นี้รันข้อมูลตั้งต้นได้ รับข้อมูลใหม่ได้ รันซ้ำไม่เพิ่มยอด ตรวจที่มาของตัวเลขได้ และถ้าพังระหว่างทางก็ทดสอบการกู้คืนได้ครับ”

## คำถามที่อาจารย์อาจถาม

**ทำไมใช้ข้อมูลจำลอง?** — “เพื่อควบคุมเคสทดสอบให้รู้ผลที่ควรได้ และให้เพื่อนรันซ้ำได้เหมือนกันครับ”

**Run 1 กับ Run 2 ต่างกันอย่างไร?** — “Run 1 สร้างข้อมูลตั้งต้นทั้งหมด ส่วน Run 2 เพิ่มหรืออัปเดตเฉพาะที่เปลี่ยนครับ”

**ถ้า Transform ล้มเหลวจะทำอย่างไร?** — “เก็บข้อมูลดิบไว้ แก้สาเหตุ แล้วรันใหม่ตั้งแต่ Transform ครับ”

**รู้ได้อย่างไรว่ารันซ้ำไม่ซ้ำจริง?** — “เทียบจำนวน Order Item กับยอดขายก่อนและหลังรัน Batch เดิมซ้ำครับ”

**Latency และ Throughput มาจากไหน?** — “วัดเวลาที่ Code ทำงานจริงใน Colab แล้วคำนวณรายการที่ประมวลผลต่อวินาทีครับ”

**อัตราค่าคอมมิชชันที่แนะนำคืออัตราที่ขายดีที่สุดหรือไม่?** — “ไม่ใช่ครับ เป็นเพดานที่ยังรักษากำไรตามสมมติฐานเดิมได้ ยังไม่ใช่การคาดการณ์ยอดขายที่จะเพิ่มขึ้น”

## สิ่งที่ไม่จำเป็นต้องเปิดโชว์

ไม่ต้องเปิด Code ทุกไฟล์ ไม่ต้องอ่านชื่อ 25 Tables หรือไล่ Log ทุกแถว ถ้าอาจารย์ถามจึงเปิด `docs/`, `pipeline/` และรายงานใน `output/main/reports/` เพิ่ม
