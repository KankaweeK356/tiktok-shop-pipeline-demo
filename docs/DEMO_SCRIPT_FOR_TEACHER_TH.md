# บทพูด Demo สำหรับอาจารย์ (ฉบับปรับปรุงตามคอมเมนต์)

## ลำดับนำเสนอให้อาจารย์ดู

### 1. แนะนำภาพรวมสถาปัตยกรรม (1 นาที)
- "อาจารย์ครับ ระบบนี้ได้รับการย้ายระบบประมวลผล ETL จากเดิมที่เคยพึ่ง GitHub Actions ให้มา**รันบน Vercel (Vercel Native Runner)** โดยตรง ทำให้เมื่อผู้ใช้กด Run ระบบจะประมวลผลเสร็จสิ้นภายในไม่กี่วินาที ไม่ต้องรอคิว VM ของ GitHub ครับ"
- "ข้อมูลถูกจัดเก็บบน Neon PostgreSQL โดยแยก Branch อย่างชัดเจน: `classroom-live-run-lab` สำหรับการรันปกติ และ `classroom-error-lab` สำหรับ Error Test เพื่อรับประกันว่าข้อมูลธุรกิจจะไม่ถูกรบกวนครับ"

---

### 2. นำเสนอการทำงานของ Pipeline และหน้าจอ Master-Detail Split View (3 นาที)
- **กด Run 1 (มกราคม 2569)**:
  - "ในแท็บขั้นตอนการรัน ผมกด **▶ รันข้อมูลตั้งต้น (Run 1)** ระบบ Vercel จะเริ่มประมวลผล 5 ขั้นตอนทันทีครับ"
- **ชี้แจง Input / Output และรายละเอียดในแต่ละขั้น (เปิดแบบ Split Screen)**:
  - "เมื่อคลิกที่ตารางใด ๆ ในแต่ละขั้น หน้าจอจะแบ่งครึ่งซ้าย-ขวา (Master-Detail): ด้านซ้ายคือรายการตาราง ด้านขวาจะแสดงจำนวนแถวจริง ชนิดข้อมูล คอลัมน์ ตัวอย่างข้อมูล 5 แถว และตาราง Dashboard ที่นำไปใช้ทันที โดยไม่ต้องเลื่อนหน้าจอลงไปข้างล่างครับ"
  - **ขั้น 1 (Source ➔ Database)**: "รับ **ไฟล์ CSV 21 ไฟล์** เข้ามา แล้วสร้างตารางคำนวณ FIFO, ค่าธรรมเนียม และคลังสินค้าเพิ่มอีก 4 ตาราง กลายเป็น **25 ตาราง Database** ใน Neon ครับ"
  - **ขั้น 2 (Database ➔ Data Lake)**: "สกัดข้อมูล 25 ตารางออกมาเป็น **25 ไฟล์ Data Lake Parquet** บีบอัดแบบ Snappy เพื่อประสิทธิภาพการคิวรีแบบ Columnar ครับ"
  - **ขั้น 3 (Transform & Quality Check)**: "ในขั้นนี้แยกให้เห็น 2 ส่วนชัดเจนคือ การจัดมาตรฐานข้อมูล (Type casting, Dates) และการตรวจกฎคุณภาพ (Quality Check เช่น Foreign Key, Null check) ครับ"
  - **ขั้น 4 (Data Lake ➔ Warehouse)**: "โหลดเข้า **ตาราง Warehouse ใน DuckDB** พร้อมแสดง Mapping ชัดเจนว่าตาราง `View_Shop_Monthly_KPI` นำไปใช้ในหน้า Business Dashboard สำหรับคำนวณ Net Revenue และเกณฑ์กำไรขั้นต่ำ 10% ครับ"
  - **ขั้น 5 (Validate)**: "แสดงเส้นทางการตรวจ Cross-Layer Reconciliation ละเอียดทุกชั้น พร้อมยืนยันตัวเลขยอดขายสุทธิ $Source = Warehouse$ 100% ครับ"

### 3. นำเสนอการเติมข้อมูลรายเดือน และการสาธิต Error ในเดือนที่ 3 (3 นาที)
- **เติมข้อมูลเดือนที่ 2 (กุมภาพันธ์)**:
  - "เมื่อกดเติมข้อมูลเดือนที่ 2 ระบบจะดึง Source ชุด `incremental_01` มาประมวลผลและผนวกเข้า Warehouse อย่างถูกต้องครับ"
- **สาธิตพบ Error ในเดือนที่ 3 (มีนาคม)**:
  - "เมื่อถึงเดือนที่ 3 เรามีปุ่มพิเศษคือ **[ ⚠️ สาธิตพบ Error ในเดือน 3 (Quality Test) ]** ครับ"
  - "เมื่อกดปุ่มนี้ ระบบจะจำลองว่าไฟล์คำสั่งซื้อมีรหัส SKU ที่ไม่มีอยู่จริงใน `Dim_SKU`"
  - "ระบบตรวจพบในขั้น Transform / Quality Check และแสดงแผงเตือนสีแดงว่า **กักข้อมูล (Quarantine) ไว้ และหยุดประมวลผลทันที**"
  - "อาจารย์จะเห็นว่า **ข้อมูลเดือน 3 จะไม่ถูกโหลดเข้า Warehouse** และข้อมูลเดือน 1-2 ยังคงสมบูรณ์ ไม่เสียหายครับ"
- **การกู้คืนและไปต่อจาก Checkpoint**:
  - "จากนั้นเรากดปุ่ม **[ 🔄 ใช้ข้อมูลฉบับแก้ไข แล้วรันต่อจาก Checkpoint ]**"
  - "ระบบจะสลับมาใช้ Source ฉบับปกติของเดือน 3 แล้วรันต่อจากจุดที่ค้างไว้ เข้าสู่ Warehouse ได้สำเร็จ โดยไม่ต้องเริ่มนับหนึ่งใหม่ตั้งแต่เดือน 1 ครับ"
