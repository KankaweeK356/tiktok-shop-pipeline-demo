# อภิธานศัพท์ (ศัพท์เทคนิค → คำไทย/ทับศัพท์ → ความหมายง่าย ๆ)

> อ่านหน้านี้ก่อน แล้วค่อยอ่านเอกสารส่วนอื่น ตัวอย่างใช้เรื่องร้านเสื้อผ้าบน TikTok Shop ของ Demo นี้

## 1) คำพื้นฐานเรื่องข้อมูล

| ศัพท์ | อ่านว่า / คำไทย | ความหมายง่าย ๆ |
|---|---|---|
| Source | ซอร์ซ / แหล่งข้อมูลต้นทาง | ที่ข้อมูลมาจาก ในที่นี้คือไฟล์ CSV ใน ZIP รายเดือน |
| CSV | ซีเอสวี / ไฟล์ตารางตัวอักษร | ไฟล์ข้อความที่คั่นคอลัมน์ด้วยจุลภาค เปิดด้วย Excel ได้ |
| Table | เทเบิล / ตาราง | ข้อมูลเรียงเป็นแถว-คอลัมน์ เช่น ตารางออเดอร์ |
| Database (DB) | ดาต้าเบส / ฐานข้อมูล | ที่เก็บตารางจำนวนมากอย่างเป็นระบบ |
| Master table / Dimension | มาสเตอร์ / ตารางข้อมูลหลัก | ข้อมูลที่ไม่ค่อยเปลี่ยน เช่น รายชื่อสินค้า, ครีเอเตอร์, voucher |
| Transaction / Fact | ทรานแซกชัน / แฟกต์ / ตารางธุรกรรม | เหตุการณ์ที่เกิดขึ้นจริง เช่น ออเดอร์, การรับสินค้า, ค่าโฆษณา (มีตัวเลขให้นำไปรวม) |
| Reference table | รีเฟอเรนซ์ / ตารางอ้างอิง | ตารางกฎ/ค่าอ้างอิง เช่น อัตราค่าธรรมเนียม |
| Primary key (PK) | พรายมารี คีย์ / คีย์หลัก | ค่าที่ระบุแต่ละแถวไม่ให้ซ้ำ เช่น เลขออเดอร์ |
| Foreign key (FK) | ฟอเรน คีย์ / คีย์นอก | ค่าที่ชี้ไปหาอีกตาราง เช่น SKU ในออเดอร์ต้องมีอยู่ในตารางสินค้า |
| SKU | เอสเคยู / รหัสสินค้าย่อย | สินค้าแต่ละแบบ (สี/ไซซ์) เช่น PG03-BR-XL |
| Product Group | โปรดักต์กรุ๊ป / กลุ่มสินค้า | กลุ่มสินค้า PG01–PG05 ที่ใช้พยากรณ์ยอดขาย |
| Normalization | นอร์มัลไลเซชัน / การทำให้ข้อมูลเป็นบรรทัดฐาน | แยกข้อมูลไม่ให้ซ้ำซ้อนหลายที่ แก้ที่เดียวถูกทุกที่ (Ch.2) |
| Bridge table | บริดจ์ / ตารางเชื่อม | ตารางที่เชื่อมความสัมพันธ์แบบหลายต่อหลาย เช่น แคมเปญ ↔ กลุ่มสินค้า |
| Schema | สกีมา / โครงสร้างตาราง | แบบแปลนว่ามีตารางอะไร คอลัมน์อะไร เชื่อมกันอย่างไร |
| Surrogate key | เซอร์โรเกต คีย์ / คีย์ตัวแทน | เลขที่ระบบสร้างขึ้นแทนรหัสธุรกิจ เพื่อเชื่อมตารางได้เร็วและเสถียร |
| Business key | บิสซิเนส คีย์ / คีย์ธุรกิจ | รหัสที่ธุรกิจใช้จริง เช่น Order_ID |
| Granularity / Grain | แกรนูลาริตี / ระดับรายละเอียด | 1 แถวแทนอะไร เช่น 1 แถว = 1 ชิ้นในออเดอร์ (Order Item) |

## 2) ชื่อชั้นระบบ (สถาปัตยกรรม)

| ศัพท์ | อ่านว่า / คำไทย | ความหมายง่าย ๆ |
|---|---|---|
| OLTP | โอแอลทีพี / ระบบฐานข้อมูลสำหรับทำรายการประจำวัน | ฐานข้อมูลที่เก็บธุรกรรมถูกต้องแม่นยำ เน้นบันทึกข้อมูล (= ER1 ของเรา) |
| ER1 / ER2 | อีอาร์วัน / อีอาร์ทู | ชื่อเรียกในโปรเจกต์: ER1 = ฐานข้อมูลต้นทาง (25 ตาราง), ER2 = คลังข้อมูล (11 ตาราง) |
| ER diagram | อีอาร์ ไดอะแกรม / แผนภาพความสัมพันธ์ตาราง | ภาพแสดงตารางและเส้นเชื่อมระหว่างกัน |
| Data Lake | ดาต้าเลค / ทะเลสาบข้อมูล | ที่พักไฟล์ข้อมูลดิบจำนวนมาก เก็บตามที่ได้มาก่อน ยังไม่ต้องจัดรูปแบบ (Ch.4) |
| Zone | โซน / พื้นที่ | แบ่ง Lake เป็นชั้นตามความสะอาด: landing → raw → standardized |
| Landing zone | แลนดิ้ง โซน / พื้นที่รับของ | จุดวางไฟล์ต้นฉบับที่เพิ่งมาถึง |
| Raw zone | รอว์ โซน / พื้นที่ข้อมูลดิบ | เก็บข้อมูลตามต้นฉบับ ไม่แก้ไข เก็บไว้ย้อนตรวจสอบ |
| Standardized / Trusted zone | สแตนดาร์ดไดซ์ด / พื้นที่ข้อมูลมาตรฐาน | ข้อมูลที่จัดรูปแบบและผ่านการตรวจคุณภาพแล้ว |
| Parquet | พาร์เก / ไฟล์คอลัมน์แบบบีบอัด | รูปแบบไฟล์เปิดสำหรับเก็บตารางขนาดใหญ่ อ่านเร็วและเล็ก |
| Object storage | ออบเจกต์ สตอเรจ / ที่เก็บไฟล์บนคลาวด์ | ที่เก็บไฟล์แบบคลาวด์ (เหมือน Google Drive สำหรับระบบ) |
| Data Warehouse (DW) | ดาต้าแวร์เฮาส์ / คลังข้อมูล | ฐานข้อมูลที่จัดไว้สำหรับวิเคราะห์ ไม่ใช่สำหรับบันทึกรายการ (Ch.5) |
| Star schema | สตาร์ สกีมา / โครงสร้างแบบดาว | Fact อยู่กลาง ล้อมด้วย Dimension เหมือนรูปดาว ทำให้ถามข้อมูลง่าย |
| Fact / Dimension | แฟกต์ / ไดเมนชัน | Fact = ตัวเลขที่วัด (ยอดขาย), Dimension = บริบท (สินค้า, วันที่, ครีเอเตอร์) |
| Conformed dimension | คอนฟอร์มด์ ไดเมนชัน / มิติกลางที่ใช้ร่วมกัน | Dimension เดียวใช้ร่วมกันหลาย Fact เช่น Dim_Date |
| Data Mart | ดาต้ามาร์ท / ตารางสรุปตามหัวข้อ | ตารางสรุปสำเร็จรูปสำหรับหัวข้อหนึ่ง (ของเราคือสรุปรายวัน×กลุ่มสินค้า) |
| View | วิว / ตารางเสมือน | ผลลัพธ์จากคำสั่งค้นหาที่ตั้งชื่อไว้ ไม่เก็บข้อมูลซ้ำ (ของเราคือ KPI รายเดือน) |
| Kimball / Inmon | คิมบอลล์ / อินมอน | ชื่อสองแนวคิดสร้าง Warehouse: Kimball = star schema, Inmon = คลังกลางแบบ normalized |
| Lakehouse | เลคเฮาส์ / ผสม Lake กับ Warehouse | Lake ที่มีความน่าเชื่อถือแบบ Warehouse (ACID) เช่น Delta/Iceberg — **ของเราไม่ใช่** |
| DuckDB | ดั๊กดีบี | โปรแกรมฐานข้อมูลเบา ๆ ที่ใช้เป็น Warehouse ของเรา |
| Neon / Postgres | นีออน / โพสต์เกรส | บริการฐานข้อมูลบนคลาวด์ที่เก็บ ER1 และไฟล์ Lake |
| Vercel | เวอร์เซล | บริการโฮสต์เว็บ Dashboard ของเรา |
| GitHub Actions | กิตฮับ แอกชันส์ | ระบบรันงานอัตโนมัติ ใช้รันแต่ละขั้นของ pipeline |
| Dashboard | แดชบอร์ด / หน้าจอสรุปผล | หน้าเว็บแสดงตัวเลขและกราฟสำหรับผู้บริหาร/ฝ่ายปฏิบัติการ |
| Mart / KPI | KPI = เคพีไอ / ตัวชี้วัดผลงานหลัก | ตัวเลขที่ใช้วัดธุรกิจ เช่น รายได้สุทธิ, กำไร |

## 3) คำเรื่อง Pipeline

| ศัพท์ | อ่านว่า / คำไทย | ความหมายง่าย ๆ |
|---|---|---|
| Pipeline | ไปป์ไลน์ / สายพานนำเข้าข้อมูล | ขั้นตอนต่อเนื่องที่พาข้อมูลจากต้นทางไปปลายทาง |
| ETL | อีทีแอล / สกัด-แปลง-โหลด | Extract (ดึง) → Transform (แปลง) → Load (โหลด) |
| ELT | อีแอลที / โหลดก่อนแปลงทีหลัง | เก็บดิบก่อนแล้วค่อยแปลงในที่เก็บ |
| Ingest | อินเจสต์ / นำเข้า | รับข้อมูลต้นทางเข้าระบบ (ขั้น 1) |
| Extract | เอกซ์แทรกต์ / ดึงออก | ดึงข้อมูลจากฐานข้อมูลออกเป็นไฟล์ (ขั้น 2) |
| Transform | ทรานส์ฟอร์ม / แปลงรูป | ทำความสะอาด จัดมาตรฐาน คำนวณ (ขั้น 3) |
| Load | โหลด / นำเข้าคลังข้อมูล | ใส่ข้อมูลเข้า Warehouse (ขั้น 4) |
| Validate | แวลิเดต / ตรวจสอบความถูกต้อง | เทียบต้นทางกับปลายทางว่าตรงกัน (ขั้น 5) |
| Batch | แบทช์ / ทำทีละชุด | ประมวลผลเป็นรอบ เช่น เดือนละครั้ง |
| Incremental load | อินครีเมนทัล โหลด / โหลดเฉพาะส่วนที่เพิ่ม/เปลี่ยน | ไม่โหลดทั้งหมดซ้ำ เอาเฉพาะข้อมูลใหม่ |
| Streaming / Real-time | สตรีมมิง / เรียลไทม์ / ประมวลผลต่อเนื่องทันที | ข้อมูลไหลเข้าทีละรายการตลอดเวลา (ของเรา**ไม่ใช่**) |
| Checkpoint | เช็กพอยต์ / จุดบันทึกความคืบหน้า | จำว่าทำถึงขั้นไหนแล้ว ล้มแล้วทำต่อได้ ไม่ต้องเริ่มใหม่ |
| Idempotent | ไอเดมโพเทนต์ / รันซ้ำได้ผลเหมือนเดิม | รันกี่รอบข้อมูลก็ไม่ซ้ำไม่เพี้ยน |
| Upsert | อัปเสิร์ต / เพิ่มหรืออัปเดต | ถ้ามีแถวนี้แล้วให้แก้ ถ้ายังไม่มีให้เพิ่ม |
| Transaction (ฐานข้อมูล) | ทรานแซกชัน / ชุดคำสั่งที่สำเร็จทั้งหมดหรือไม่ทำเลย | กันข้อมูลครึ่ง ๆ กลาง ๆ |
| Rollback / Commit | โรลแบ็ก / คอมมิต | ยกเลิกทั้งชุด / ยืนยันบันทึกทั้งชุด |
| Data Quality (DQ) | ดาต้า ควอลิตี / คุณภาพข้อมูล | ตรวจว่าข้อมูลครบ ไม่ซ้ำ อ้างอิงถูก |
| DQ rule | ดีคิว รูล / กฎตรวจคุณภาพ | เช่น "คีย์หลักต้องไม่ซ้ำ", "ห้ามว่าง", "ต้องมีแม่ในตารางอ้างอิง" |
| Blocking | บล็อกกิ้ง / ตกแล้วหยุดทั้งหมด | ข้อผิดพลาดร้ายแรง ไม่ปล่อยผ่านไปขั้นต่อไป |
| Quarantine | ควอรันทีน / กักกัน | เก็บข้อมูลที่มีปัญหาแยกไว้ตรวจสอบ |
| Reconciliation | รีคอนซิลิเอชัน / การกระทบยอด | เทียบยอดสองฝั่งว่าตรงกัน เหมือนกระทบยอดบัญชี |
| Lineage | ลินีเอจ / เส้นทางที่มาของข้อมูล | ตามรอยย้อนกลับได้ว่าแต่ละตัวเลขมาจากไฟล์ไหน |
| Metadata | เมทาดาต้า / ข้อมูลอธิบายข้อมูล | เช่น จำนวนแถว, ค่า hash, เวลาที่สร้าง |
| SHA-256 / Hash | แฮช / ลายนิ้วมือของไฟล์ | รหัสสั้น ๆ ที่เปลี่ยนทันทีถ้าไฟล์ถูกแก้ ใช้พิสูจน์ว่าไฟล์ไม่ถูกแตะ |
| Overlay | โอเวอร์เลย์ / ชั้นแก้ไขซ้อนทับ | แก้ข้อมูลผิดโดยไม่แตะไฟล์ต้นฉบับ แยกเป็นชั้นแก้ไข |
| Publish Snapshot | พับลิช สแนปช็อต / ประกาศเผยแพร่ข้อมูลเดือนนั้น | หลังตรวจผ่าน ปล่อยให้ Dashboard/Forecast ใช้ข้อมูลเดือนนั้น |
| Fail-closed | เฟลโคลสด์ / ไม่แน่ใจให้ปิดไว้ก่อน | ถ้าตรวจไม่ผ่านจะไม่เผยแพร่ |
| Defense in depth | ดีเฟนส์ อินเดปธ์ / ป้องกันหลายชั้น | ตรวจหลายด่านซ้ำ เผื่อด่านหนึ่งพลาด |

## 4) คำเรื่อง Forecast / ML

| ศัพท์ | อ่านว่า / คำไทย | ความหมายง่าย ๆ |
|---|---|---|
| Forecast | ฟอร์แคสต์ / การพยากรณ์ | คาดการณ์ยอดขายเดือนหน้า |
| Actual | แอคชวล / ค่าจริง | ยอดขายที่เกิดขึ้นจริง |
| Net Revenue | เน็ต เรเวนิว / รายได้สุทธิ | ยอดขายหลังหักส่วนลดแคมเปญ/voucher |
| Gross | กรอส / ยอดรวมก่อนหัก | ราคาเต็ม × จำนวน |
| COGS | ค็อกส์ / ต้นทุนสินค้าที่ขาย | ต้นทุนของสินค้าที่ขายออกไป |
| Contribution Profit | คอนทริบิวชัน โปรฟิต / กำไรส่วนเกิน | รายได้สุทธิ หักต้นทุนและค่าใช้จ่ายผันแปรต่าง ๆ |
| Baseline | เบสไลน์ / วิธีมาตรฐานพื้นฐาน | วิธีง่าย ๆ ที่ใช้เป็นเกณฑ์เทียบ (ของเรา: ยอดเดือนก่อน หรือเฉลี่ย 3 เดือน) |
| Naive | ไนอีฟ / วิธีซื่อ ๆ | ทายว่าเดือนหน้าเท่าเดือนก่อน |
| Trailing 3-month mean | เทรลลิง / ค่าเฉลี่ยย้อนหลัง 3 เดือน | เฉลี่ยยอด 3 เดือนล่าสุด |
| ML (Machine Learning) | เอ็มแอล / การเรียนรู้ของเครื่อง | ให้คอมพิวเตอร์เรียนรู้รูปแบบจากข้อมูลอดีต |
| Ridge regression | ริดจ์ รีเกรสชัน / การถดถอยแบบริดจ์ | สมการทำนายตัวเลขที่มีตัวคุมไม่ให้ซับซ้อนเกินไป (กัน overfitting) |
| Feature | ฟีเจอร์ / ตัวแปรที่ใช้ทำนาย | เช่น ยอดเดือนก่อน, จำนวนวันในเดือน |
| Feature Store | ฟีเจอร์ สโตร์ / คลังตัวแปรสำหรับโมเดล | ที่เก็บตัวแปรไว้ใช้ซ้ำ เก็บค่า "ณ เวลานั้น" |
| Point-in-time | พอยต์-อิน-ไทม์ / ใช้ข้อมูล ณ เวลานั้นจริง | ไม่เอาข้อมูลอนาคตมาปน |
| Data leakage | ดาต้า ลีกเกจ / ข้อมูลรั่วจากอนาคต | โมเดลแอบเห็นคำตอบ ทำให้ดูแม่นเกินจริง |
| Walk-forward | วอล์กฟอร์เวิร์ด / ทดสอบย้อนทีละเดือน | ย้อนไปทำนายเดือนอดีตด้วยข้อมูลที่มี ณ ตอนนั้น แล้วเทียบกับของจริง |
| Origin | ออริจิน / จุดเริ่มต้นการทำนายหนึ่งครั้ง | เดือนที่ "ยืนอยู่" ตอนทำนายเดือนถัดไป (ต้องมี ≥3 จุดถึงเทียบ ML ได้) |
| WAPE | วาเป้ / ร้อยละความคลาดเคลื่อนถ่วงน้ำหนัก | Σ ความต่าง ÷ Σ ยอดจริง ยิ่งต่ำยิ่งแม่น |
| MAE | เอ็มเอไอ / ค่าคลาดเคลื่อนเฉลี่ยสัมบูรณ์ | พลาดเฉลี่ยกี่บาทต่อครั้ง |
| Bias | ไบแอส / ความเอนเอียง | ทายสูงไปหรือต่ำไปโดยเฉลี่ย (Forecast − Actual) |
| pp (percentage point) | พีพี / จุดเปอร์เซ็นต์ | ผลต่างของ % เช่น 12% กับ 10% ต่างกัน 2 pp |
| Seal | ซีล / ล็อกผลพยากรณ์ | ล็อกไม่ให้แก้ย้อนหลัง |
| Shadow ML | แชโดว์ เอ็มแอล / ML ที่รันเงียบ ๆ ข้างหลัง | บันทึกคำทำนายไว้เทียบ แต่ยังไม่ใช้ตัดสินใจจริง |
| Champion–Challenger | แชมเปี้ยน–แชลเลนเจอร์ / ตัวหลัก–ตัวท้าชิง | Baseline = แชมป์ปัจจุบัน, ML = ตัวท้าชิงที่ต้องพิสูจน์ว่าชนะ |
| MLOps | เอ็มแอลออปส์ / การดูแลระบบ ML ให้ใช้งานจริงต่อเนื่อง | ทั้งการทดสอบ ตรวจสอบ เฝ้าระวัง โมเดล (Ch.7) |
| Monitoring | มอนิเตอริง / การเฝ้าติดตาม | ดูว่าโมเดลยังแม่นอยู่ไหมเมื่อเวลาผ่านไป |
| Scenario / Plan | ซีนาริโอ / แผน | แผนงบ Ads/คูปองที่เลือกไว้ (ไม่มีผลต่อ Forecast และ Actual) |
| Ads / Voucher / Campaign | แอดส์ / วาวเชอร์ / แคมเปญ | โฆษณา / คูปองส่วนลด / ชุดโปรโมชัน |
| Affiliate / Creator | แอฟฟิลิเอต / ครีเอเตอร์ | คนขายผ่านลิงก์ที่ได้ค่าคอมมิชชัน / ผู้ทำคอนเทนต์ |
| Synthetic data | ซินเธติก ดาต้า / ข้อมูลสังเคราะห์ | ข้อมูลที่สร้างขึ้นเพื่อการเรียน ไม่ใช่ข้อมูลจริง |

## 5) คำเรื่องการนำเสนอ

| ศัพท์ | อ่านว่า / คำไทย | ความหมายง่าย ๆ |
|---|---|---|
| Stakeholder | สเตกโฮลเดอร์ / ผู้มีส่วนได้ส่วนเสีย | คนที่เกี่ยวข้องกับธุรกิจ เช่น ผู้บริหาร ฝ่ายการตลาด |
| Role-based dashboard | โรลเบสด์ แดชบอร์ด / แดชบอร์ดตามบทบาท | หน้าจอแยกตามผู้ใช้ เช่น ผู้บริหาร / ฝ่ายปฏิบัติการ |
| Live demo | ไลฟ์ เดโม / สาธิตสด | รันระบบจริงให้ดูต่อหน้า |
| Consulting-style | คอนซัลติ้ง สไตล์ / นำเสนอแบบที่ปรึกษา | เล่าจากปัญหาธุรกิจ → วิธีแก้ → ผลลัพธ์ มากกว่าเล่าแต่เทคนิค |
| End-to-end | เอนด์ทูเอนด์ / ตั้งแต่ต้นจนจบ | ครบทั้งสายตั้งแต่ข้อมูลต้นทางจนถึงผลลัพธ์ |
| Rubric | รูบริก / เกณฑ์การให้คะแนน | ตารางเกณฑ์ที่อาจารย์ใช้ให้คะแนน |
